# PlugMyBrain

The memory brain itself. Three commands, and everything else is markdown.

@README.md

## Before You Search This Repository

**Code structure comes from the map, not from grepping.** `graph/plugmybrain/graphify-out/graph.json`
is an AST map extracted by tree-sitter, and reading it costs no model tokens. Query it instead
of walking the tree:

```bash
graphify query "where is the vector index created" --graph graph/plugmybrain/graphify-out/graph.json
graphify god-nodes --graph graph/plugmybrain/graphify-out/graph.json
```

If the map is stale, rebuild it with `pmb digest` rather than reading files to compensate.

## The Three Commands Are the Whole Surface

`pmb digest`, `pmb reset`, `pmb list`. There is no search command, no export command, no note
command. Do not add one back because a task would be easier with it; the surface is small on
purpose, and a fourth command needs the user to ask for it.

The folder is the unit. `pmb digest <folder>` makes that folder a memory named after itself.
`memory/` inside it is human-authored and survives `reset`; `graph/` is generated and does not.

## The PlugMyBrain MCP Server

At `http://127.0.0.1:9000/mcp`, whether the stack runs here or on the VM behind the tunnel.

**Read with `recall`, always passing `datasets`.** A memory is named after the folder it came
from, lowercased. `pmb list` shows which ones exist.

```json
{"query": "why is there no licence", "datasets": ["plugmybrain"],
 "search_type": "CHUNKS", "top_k": 15}
```

`search_type: "CHUNKS"` returns sourced passages with no second model call. Use
`GRAPH_COMPLETION` only when you actually want prose synthesised, because it costs an extra
call on a path that runs on every question.

Passing `datasets` narrows the answer but does not fence it. This is stock `cognee-mcp`, and
Cognee keeps every memory in one vector collection, so a foreign document can still come back.
Check the source file before citing it.

## Two Things Not to Do

- **Never call `remember` or `forget`.** They are exposed by the MCP server and they write
  straight into the index, which the next `pmb digest` overwrites. The memory is markdown:
  write a note into the folder's `memory/`, then digest. A note that exists only in Cognee is
  already gone, and nothing will warn you.
- Do not hand-edit anything under a folder's `graph/`. It is regenerated by every digest and
  deleted by every reset. If something there is worth keeping, move it into `memory/` yourself
  and write down why.

## Digest in the Container, Never on Windows

The native run hangs on Cognee's subprocess database workers, and a killed run writes host
paths into Postgres that a later container run cannot read.

```bash
docker compose run --rm -v "$FOLDER:/w/$NAME" pmb digest "/w/$NAME"
```

The mount path carries the folder's name because that name is the memory it lands in.
